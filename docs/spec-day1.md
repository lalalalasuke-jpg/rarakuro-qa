## 1. 1日目の概要

- 担当: **神経衰弱 ハロウィンイベント v1.3**
- 1日は **朝・昼・夕** の3ターン。足りなければ **残業**、最後に **終業前**
- 1日目に仕込まれるバグは、**7つのバグ候補からランダムに3つ**（遊ぶたびに変わる）
- プレイヤーは作中タイトルを遊んでバグを見つけ、報告書を出す → 次のターンに開発さんから返事 → 直ったら修正確認
- 3つとも直って修正確認が済んだら（または残業中に「今日はあがる」を押したら）**1日の結果**

## 3. 1日の進み方（ターン）

### ターンの順番

```
朝 → 昼 → 夕 → 残業1 → 残業2 → …（3つ全部直るまで）
                     ↘ 全部直ったら → 終業前 → 1日の結果
```

- **ターンが終わる**のは、報告書を提出できたとき、または「異常なし」を押したとき
  - 「本当に見た？」で止められた報告は提出にならない（ターンは進まない）
- **次のターンの始め**に、前のターンで出した報告の返事が開発さんから届く
- 返事が「修正します」なら、そのバグは**次のターンから直っている**
- ターンが変わるたびに、作中タイトルは最初からになる
- 「見たバグ」の記録はターンごとにリセットされる（修正版で本当に起きるかは見直さないと分からないため）

### いつ終わるか

| 条件 | どうなる |
|---|---|
| 夕方までに3つとも直った | 次は「終業前」→ 修正確認 → 1日の結果（定時で完了） |
| 夕方の時点でまだ直っていないバグがある | 残業ターンへ。全部直るまで続く |
| 残業中に「今日はあがる」 | すぐ1日の結果（直っていないバグは「見逃し」） |

### ターンの始めに話す人

| 状況 | 話し手と内容 |
|---|---|
| 朝（1日の始め） | リーダー: 担当の連絡（10章） |
| 前のターンに報告を出した | 開発さん: 返事（7章）。「修正します」なら 1.8 秒後にリーダーが修正確認を頼む |
| 前のターンが「異常なし」 | リーダー: そのターンのひとこと（10章） |

## 5. バグ候補（7つ）

1日目は、この7つから毎回ランダムに3つが仕込まれる。

### 一覧

| ID | 種類 | 内容 | 起こし方 | 症状 |
|---|---|---|---|---|
| MM-HW-001 | 見た目 | 1種類だけ通常の絵柄のまま | キャンディのカードをめくる | 青い丸に「F」の通常絵柄で表示される |
| MM-HW-002 | 挙動 | 素早くタップすると3枚めくれる | 2枚目をめくってから 0.5 秒以内に3枚目をタップ | 3枚目も表になる（判定後、3枚とも裏に戻る） |
| MM-HW-003 | 仕様違い | クリア報酬が×1 | 全ペアをそろえてクリア | 「報酬：かぼちゃメダル ×1」 |
| MM-HW-004 | 仕様違い | ペアがそろった時に手数が増えない | 同じ絵柄の2枚をめくってペアをそろえる | そろった時だけ MOVES が増えない |
| MM-HW-005 | 見た目 | イベント期間の表示が1日短い | ゲーム画面を見る | バナーが「10/26 - 10/30」 |
| MM-HW-006 | 挙動 | 同じカードを2回タップすると1枚でペア | 1枚目をめくったあと、同じカードをもう一度タップ | その1枚だけでペア成立（相方が残り、クリアできなくなることがある → 再起動） |
| MM-HW-007 | 挙動 | おばけとドクロがペアになる | おばけとドクロを続けてめくる | 違う絵柄なのにペア成立 |

### 報告書の正解

| ID | どこで | 何をしたら（再現手順） | 何が | 期待する動き | 実際の動き | 重要度 | 手順が違っても直る |
|---|---|---|---|---|---|---|---|
| 001 | プレイ中の盤面 | カードを1枚めくる | カードの絵柄 | 8種類すべてハロウィン絵柄 | ハロウィン絵柄ではないカードがある | 低 または 中 | ○ |
| 002 | プレイ中の盤面 | 2枚目をめくった直後に、素早く3枚目をタップする | めくれるカードの枚数 | 1回にめくれるのは2枚まで | 3枚目もめくれる | 中 | × |
| 003 | クリア画面 | 全ペアをそろえてクリアする | クリア報酬の数 | クリアで「かぼちゃメダル」×3 | メダルが×1しかもらえない | 高 | ○ |
| 004 | 手数・ペア数の表示 | 同じ絵柄の2枚をめくってペアをそろえる | 手数の表示 | 2枚めくるたびに手数が1増える | ペアがそろった時に手数が増えない | 低 | × |
| 005 | イベントバナー | ゲーム画面を開く | イベント期間の表示 | 期間は10/26〜10/31 | 期間の表示が違う | 中 | ○ |
| 006 | プレイ中の盤面 | 同じカードを2回タップする | ペアの判定 | 同じ絵柄の2枚でペア成立 | 1枚だけでペアになる | 高 | × |
| 007 | プレイ中の盤面 | おばけとドクロのカードをめくる | ペアの判定 | 同じ絵柄の2枚でペア成立 | 違う絵柄なのにペアになる | 高 | × |

「手順が違っても直る」＝マスタ設定（画像・報酬・期間）を直せば済むバグ。手順が違っても開発さんは修正してくれる（手順の点は入らない）。

### 「見た」と「修正確認」になる操作

そのバグが起きるはずの操作をしたとき、バグが**出たら「見た」**、**出なかったら（直っていれば）「修正確認」**になる。

| ID | 判定される操作 |
|---|---|
| 001 | キャンディのカードをめくった |
| 002 | 2枚目をめくってから 0.5 秒以内に、裏のカードを押した |
| 003 | クリア画面が出た |
| 004 | ペアがそろった |
| 005 | そのプレイで最初にカードを触った（＝画面を見ている） |
| 006 | 1枚だけ表のとき、そのカードをもう一度押した |
| 007 | おばけとドクロを続けてめくった |

## 6. 不具合報告書

### 流れ

1. 机の「報告書」で開く
2. **1ページに1項目**ずつ選ぶ（全6ページ）。選ぶまで「次へ」は押せない。「← 戻る」で前のページへ
3. 最後に**確認ページ**（選んだ内容の一覧）→「提出する」
4. 「閉じる ×」で閉じても、選んだ内容とページは残る。提出が通ったら空に戻る

### 項目

| ページ | 項目 | ヒント（画面に出る文） |
|---|---|---|
| 1 | どこで | 不具合が起きた画面・場所はどこ？ |
| 2 | 何をしたら（再現手順） | どんな操作をすると起きる？ |
| 3 | 何が | おかしかったのは何？ |
| 4 | 期待する動き | 本当はどうなるべき？（仕様メモを見てみよう） |
| 5 | 実際の動き | 実際にはどうなった？ |
| 6 | 重要度 | どのくらい困る不具合？ |

### 選択肢の作り方

- 1〜5ページ: **7つのバグ候補すべての正解**（重複は1つにまとめる）＋**ダミー**（どのバグにも当てはまらない文）。並び順は1日ごとにシャッフル
- 6ページ: 「低」「中」「高」の3つ（固定）

| 項目 | ダミー |
|---|---|
| どこで | タイトル画面／仕様メモ |
| 再現手順 | ゆっくり1枚ずつめくる／カードを長押しする |
| 何が | カードの裏面／ペア数の表示 |
| 期待する動き | ペアがそろったカードは消える／クリアで「かぼちゃメダル」×5 |
| 実際の動き | カードがめくれない／クリア画面が出ない |

## 7. 報告の判定と開発さんの返事

### 判定の順番

提出すると、上から順に判定する。

| 順 | 条件 | 結果 | ターン |
|---|---|---|---|
| 1 | 「実際の動き」がどれかのバグ候補と一致し、そのバグを**このターンにまだ見ていない** | 「本当に見た？」で止める（リーダーのチャット）。提出にならない | 進まない |
| 2 | 「実際の動き」がどのバグ候補とも一致しない（ダミーを選んだ） | **仕様です** | 進む |
| 3 | 再現手順が正しい、または「手順が違っても直る」バグ | **修正します** | 進む |
| 4 | それ以外（手順が違う） | **再現しません**（バグは残るので出し直せる） | 進む |

- 今日は仕込まれていないバグや、もう直ったバグは画面に出ないので、報告しようとすると1の「本当に見た？」で止まる
- 「重複です」の返事も用意してあるが、今の作りでは上の理由で出ることはない（同じバグを複数の人が報告するような日のために残している）
- 「どこで／何が／期待する動き」が違っていても、修正はしてもらえる（点数が減るだけ）

### 開発さんの返事（次のターンの始め）

「◯◯」には報告の「実際の動き」が入る。

| 結果 | 返事 |
|---|---|
| 修正します | 「◯◯」の件、修正しました！修正版をもう入れてあります。 |
| 修正します（手順は違った） | 「◯◯」の件、手順は少し違ったけど原因は分かったので修正しました！修正版をもう入れてあります。 |
| 再現しません | 「◯◯」の件、書いてある手順だと再現しませんでした…。手順をもう一度確認してもらえますか？ |
| 仕様です | 「◯◯」の件、確認しましたが仕様どおりの動きです。 |
| 重複です | 「◯◯」の件は、もう報告をもらっています。 |

## 8. 修正確認

1. 「修正します」の返事が届いたターンは、まず修正確認をする
2. 返事の 1.8 秒後、リーダーが「まずは直ってるか確認しよっか。『（そのバグの正しい再現手順）』をやってみて、バグが出ないか見てみてね。」
3. 確認が済むまで、報告書と異常なし（今日はあがる）は押せない
4. 5章の「判定される操作」をして、バグが出なければ確認完了
   - モニターの上に緑の「**修正確認完了！**」が出る（約1.6秒で消える）
   - リーダー「ちゃんと直ってるね！じゃあ、ほかに不具合がないか探してみよう。」→ ボタンが押せるようになる
5. **終業前**の確認が済んだら、リーダー「全部直ってるね！今日はこれで終わり、おつかれさま。」→ 1.8 秒後に1日の結果

## 9. 採点と1日の結果

### 報告1件の点数（100点満点）

| 項目 | 点 |
|---|---|
| 実際の動き（バグを特定できた） | 40 |
| 再現手順 | 20 |
| どこで | 10 |
| 何が | 10 |
| 期待する動き | 10 |
| 重要度 | ぴったり 10／1段ずれ 5／2段ずれ（低↔高）0 |

- 「修正します」になった報告だけ加点。「仕様です」「再現しません」は **−10点**（「重複です」も −10点）
- 重要度の正解が2つあるバグ（001）は、近いほうで判定

### 1日のスコア

- スコア＝報告の点数の合計 − 残業1ターンにつき10点（0点より下にはならない）
- 満点＝300点（バグ3つ×100点）
- ランク: **S** 90%以上（270〜）／**A** 75%以上（225〜）／**B** 50%以上（150〜）／**C** それ未満
- ベストスコアは端末（ブラウザ）に保存。超えたら「（新記録！）」

### 結果画面に出るもの

- スコア・ランク・ベスト
- 見つけて直ったバグ ◯/3、修正確認 ◯/◯
- 「定時で完了！」または「残業 Nターン（−N×10点）」
- 提出した報告ごと: ターン名・実際の動き・開発の返事と点数・どこで／手順／何が／期待する動きの○×・重要度の○△×
- 見逃したバグ（直らなかったもの）: タイトルと起こし方
- ボタン: 「もう一度1日目」（バグもランダムで選び直し）／「2日目へ」（2日目の仕様は [spec-day2.md](spec-day2.md)）

## 13. テストの観点（メモ）

全部できあがってからテストするときの見どころ。

- 7つのバグそれぞれ: 起こせるか／報告して直るか／修正確認できるか
- 手順違い: 手順が大事なバグ（002/004/006/007）は「再現しません」、大事でないバグ（001/003/005）は修正される
- 見ていないバグ・直ったバグを報告 →「本当に見た？」で止まり、ターンが進まない
- 存在しない動き（ダミー）を報告 →「仕様です」で −10点
- 残業: 夕方までに直らない → 残業1、2…と続く／「今日はあがる」で見逃しが出る
- 修正確認中・終業前にボタンが押せない
- 点数の計算が9章どおりか（ランクの境目 270・225・150）
- 報告書: 閉じても選んだ内容が残る／提出後は空に戻る／戻るで選び直せる
- 「もう一度1日目」でバグの組み合わせが変わる
- スマホでの見た目・タップ（報告書のページ送り、再起動ボタンの押しやすさ）
