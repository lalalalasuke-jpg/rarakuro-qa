# バグの裏側（ららくろそふとQA）

ゲームの中で見つけてもらうバグが、**プログラムの中でどうやって起きているか**の解説。
1日の結果に出る「開発さんの原因メモ」の、もっと詳しい版。コードを読みながら「1〜2行の違いで、こんなふうに壊れるんだ」を体験するための資料。

- 対象: 神経衰弱 v1.3 の7個（MM-HW-001〜007）、スイカゲーム v2.1 の14個（SK-01〜14）
- コードの中には `★バグ MM-HW-002` のような目印が付いている。エディタで `★バグ` を検索すると、全部の場所が見つかる
- 行番号はコードを直すとずれるので、この資料では「ファイル」と「関数（func の名前）」で場所を書いている

## 1. まずは仕組み：バグの「スイッチ」

作中のゲームは、**正しい動き**を書いたプログラムの途中に「**このバグが ON なら、わざと間違える**」という分かれ道を置いている。

```gdscript
# どのバグが ON かを覚えておく（その日に選ばれた3つの ID が入る）
var bugs: Array = []

# 「このバグは ON？」を答える小さな関数
func has_bug(id: String) -> bool:
	return bugs.has(id)
```

使うときはこんな形になる。

```gdscript
# 正しい報酬は 3。MM-HW-003 が ON のときだけ 1 になる
var medals := BUG_003_MEDALS if has_bug("MM-HW-003") else CLEAR_MEDALS
```

- `A if 条件 else B` は「条件が正しければ A、そうでなければ B」という書き方
- 開発さんが「修正しました」と言うと、その日の `bugs` からその ID が外れる → 次のプレイから `has_bug` が false になって、正しい動きに戻る
- 実際のゲーム開発では、バグは「うっかり」入るもの。このゲームでは学ぶために**わざと・確実に**起きるように作っている（いつ遊んでも同じ条件で再現できる）

---

## 2. 「見た」と「修正確認」の見分け方

「本当に見た？」や「修正確認完了！」は、作中のゲームが出す合図（シグナル）で判定している。

```gdscript
# 「そのバグが起きるはずの操作をした」ときに呼ぶ
func _check(id: String) -> void:
	bug_checked.emit(id, has_bug(id))
```

- バグが **ON** の状態で操作した → `true`（バグが画面に出た＝**見た**）
- バグが **OFF**（直った）状態で同じ操作をした → `false`（バグが出なかった＝**修正確認**）

オフィス画面（`scenes/main.gd`）はこの合図を受け取って、「見たバグ」の一覧や修正確認の状態を更新している。

## 3. 神経衰弱のバグ（7個）

コードは `scenes/titles/memory_match/memory_match.gd`。

### MM-HW-001 1種類だけ通常の絵柄のまま

- **起きること**: キャンディのカードが、ハロウィン絵柄ではなく青い丸に「F」で出る
- **原因メモ**: キャンディの絵柄だけ、ハロウィン版への差し替えが漏れていました
- **場所**: `_build_grid()`（カードを並べるところ）

```gdscript
# ★バグ MM-HW-001
card.halloween = not (has_bug("MM-HW-001") and idx == BUG_001_SYMBOL)
```

- 正しくは全部のカードが `halloween = true`。バグのときだけ、5番目の絵柄（キャンディ）が `false` になり、カードを描く側（`card.gd`）が通常版の絵を描く
- 現場でいうと「画像の差し替えリストに1つ書き忘れた」タイプ。**マスタ（設定）の修正**で直るので、手順が違っても直してもらえる

### MM-HW-002 素早くタップすると3枚めくれる

- **起きること**: 2枚目をめくって 0.5 秒以内に3枚目を押すと、3枚目も表になる
- **原因メモ**: 判定を始めるまでの 0.5 秒間、「操作を受け付けない」状態にしていませんでした
- **場所**: `_on_card_pressed()`

```gdscript
if has_bug("MM-HW-002"):
	# ★バグ MM-HW-002: 判定を始めるまで少し待つ間 busy にしていない
	await get_tree().create_timer(BUG_002_WINDOW).timeout
busy = true
```

- `busy`（いそがしい）が true の間は、カードを押しても無視される
- 正しくは、2枚目をめくったら**すぐ** `busy = true`。バグのときは 0.5 秒待ってから true にするので、その間だけ3枚目が押せる
- こういう「ほんの一瞬だけ起きる」バグは**タイミングのバグ**と呼ばれ、現場でも再現手順が大事になる（だから手順が違うと「再現しません」になる）

### MM-HW-003 クリア報酬が×1

- **起きること**: クリア画面の報酬が「かぼちゃメダル ×1」
- **原因メモ**: クリア報酬の数の設定が、イベント仕様の3ではなく1になっていました
- **場所**: `_on_clear()`

```gdscript
# ★バグ MM-HW-003
var medals := BUG_003_MEDALS if has_bug("MM-HW-003") else CLEAR_MEDALS
```

- `CLEAR_MEDALS = 3`（正しい）、`BUG_003_MEDALS = 1`（間違い）。運営でよくある「報酬の数のマスタ設定ミス」

### MM-HW-004 ペアがそろった時に手数が増えない

- **起きること**: ペアがそろったときだけ MOVES が増えない
- **原因メモ**: ペアがそろったときだけ、手数を1増やす処理を飛ばしていました
- **場所**: `_on_card_pressed()`

```gdscript
# ★バグ MM-HW-004
if not (same and has_bug("MM-HW-004")):
	moves += 1
```

- `same` は「2枚が同じ絵柄か」。正しくは毎回 `moves += 1`（手数を1増やす）。バグのときは「そろった」場合だけ飛ばす
- 画面を注意して見ないと気づかない、**数字のバグ**

### MM-HW-005 イベント期間の表示が1日短い

- **起きること**: バナーが「10/26 - 10/30」
- **原因メモ**: バナーの期間の文言が、古い案（10/30まで）のままでした
- **場所**: `start()`

```gdscript
# ★バグ MM-HW-005
banner_label.text = BUG_005_BANNER if has_bug("MM-HW-005") else BANNER_TEXT
```

- 文字（テキスト）の設定ミス。**仕様メモと見比べる**と気づける

### MM-HW-006 同じカードを2回タップすると1枚でペア

- **起きること**: 1枚目をめくったあと同じカードをもう一度押すと、その1枚だけでペア成立になる（相方が残ってクリアできなくなることがある）
- **原因メモ**: 「同じカードかどうか」を確かめずに、そのカード1枚だけでペア成立にしていました
- **場所**: `_on_card_pressed()`

```gdscript
if flipped.size() == 1 and flipped[0] == card:   # 表のカードをもう一度押した
	if has_bug("MM-HW-006"):
		# ★バグ MM-HW-006
		card.set_matched()
		matches += 1
```

- 正しくは「表のカードを押しても何もしない」。バグのときはペア成立の処理をしてしまう
- 「同じボタンを2回押す」はテストの定番。**想定外の操作**で壊れるタイプ

### MM-HW-007 おばけとドクロがペアになる

- **起きること**: 違う絵柄なのにペア成立
- **原因メモ**: ペアの判定に、おばけとドクロを同じ絵柄とみなす間違った条件が入っていました
- **場所**: `_is_pair()`

```gdscript
func _is_pair(a, b) -> bool:
	if a.symbol_index == b.symbol_index:
		return true
	# ★バグ MM-HW-007
	return has_bug("MM-HW-007") and BUG_007_PAIR.has(a.symbol_index) and BUG_007_PAIR.has(b.symbol_index)
```

- 正しくは1行目（同じ番号ならペア）だけ。バグのときは「1番（おばけ）と6番（ドクロ）の組み合わせ」もペアにしてしまう
- どちらも白っぽい絵なので、実際の現場なら「似た画像のIDを取り違えた」ようなミス

## 4. スイカゲームのバグ（14個）

コードは `scenes/titles/suika/suika.gd`。果物の「段階」は 0 から数える（0=さくらんぼ、1=いちご、2=ぶどう、3=デコポン、4=かき、5=りんご…）。

### SK-01・SK-11・SK-12 バナー（誤字・表示されない・文字化け）

- **原因メモ**: 誤字（「覚」→「角」の変換ミス）／文言が空っぽ／文字コードが合っていない
- **場所**: `start()`

```gdscript
# ★バグ SK-01 / SK-11 / SK-12
if has_bug("SK-11"):
	banner_label.text = ""               # 何も表示しない
elif has_bug("SK-12"):
	banner_label.text = BUG_12_BANNER    # 文字化けした文字
elif has_bug("SK-01"):
	banner_label.text = BUG_01_BANNER    # 誤字
else:
	banner_label.text = BANNER_TEXT      # 正しい「秋の味覚フェア」
```

- 3つとも同じ場所なので、**同じ日には1つしか出ない**ようにしている（データの `group: "banner"`）
- **文字化け**のしくみ: 「秋の味覚フェア」を UTF-8 という形式で保存した文字を、Shift_JIS という別の形式だと思って読むと「遘九縺ｮ蜻ｳ隕壹ヵ繧ｧ繧｢」になる。くろすけが実際にこの変換をして作った文字化け（1文字だけ、フォントに入っていない「�」を、文字化けでよく出る「縺」に置き換えた）

### SK-02 NEXT と違う果物が出る

- **原因メモ**: NEXT に表示した果物ではなく、1つずれた果物を使っていました
- **場所**: `_spawn_next()`

```gdscript
var rank := next_rank            # NEXT に出ていた果物
if has_bug("SK-02"):
	# ★バグ SK-02
	rank = (rank + 1) % (SPAWN_MAX_RANK + 1)
```

- `% 3` は「3で割った余り」。0→1、1→2、2→0 とずれる。**表示と中身が別々の変数**になっているときに起きやすいバグ

### SK-03 右の壁ぎりぎりで箱の外に落ちる

- **原因メモ**: 右の壁の当たり判定がオフ＋右に寄せられる範囲が壁の外まで広がっていました
- **場所**: `start()` と `_clamp_x()`

```gdscript
# ★バグ SK-03（start の中）
right_wall.disabled = has_bug("SK-03")       # 右の壁の当たり判定を消す

# ★バグ SK-03（_clamp_x の中）
if has_bug("SK-03"):
	hi = BIN_RIGHT + r * 0.3                  # 右の限界を壁より外に
```

- **当たり判定**＝物同士がぶつかるかを決める見えない形。線（見た目）は描いてあるのに、当たり判定だけ無いので、すり抜けて落ちる
- 2か所の間違いが重なって初めて起きる。片方だけなら気づきにくい

### SK-04 いちごとぶどうが合体する

- **原因メモ**: 合体の判定に、いちごとぶどうを同じ果物とみなす間違った条件が入っていました
- **場所**: `_on_contact()`（果物がぶつかったとき）

```gdscript
if ranks.has(1) and ranks.has(2):        # いちご(1)とぶどう(2)がぶつかった
	if has_bug("SK-04"):
		# ★バグ SK-04
		_resolve_merge.call_deferred(a, b, 3)   # デコポン(3)にしてしまう
```

### SK-05 かきのボーナスが入らない

- **原因メモ**: かきを作ったときにイベントボーナス（＋50点）を足す処理が抜けていました
- **場所**: `_resolve_merge()`（合体したとき）

```gdscript
var gained := (new_rank + 1) * 10 * multiplier   # ふつうの点数（かき＝50点）
if new_rank == KAKI_RANK:
	if not has_bug("SK-05"):   # ★バグ SK-05
		gained += KAKI_BONUS     # ＋50点
```

- SK-13（デコポン→りんご）と同じ日に出ると、**かきが作れない**のでボーナスを確かめられない。バグがバグを隠す＝**影響範囲**の例

### SK-06 コンボで点数が倍にならない

- **原因メモ**: コンボの回数は数えていましたが、点数に掛け算していませんでした
- **場所**: `_resolve_merge()`

```gdscript
var multiplier := combo         # コンボの回数（2回目なら2）
if combo >= 2:
	if has_bug("SK-06"):
		multiplier = 1          # ★バグ SK-06: いつも×1
```

- 画面には「COMBO x2」と出るのに、点数は増えない。**表示は正しいのに計算が違う**ので、「+N」の数字を見ないと気づけない

### SK-07・SK-14 どんぐり（1000点ごと・0個）

- **原因メモ**: 「何点ごとに1個」の設定が1000／計算の処理が入っていない
- **場所**: `acorns_for()`（どんぐりの数を出す関数）

```gdscript
func acorns_for(s: int) -> int:
	if has_bug("SK-14"):
		return 0                                       # ★バグ SK-14
	if has_bug("SK-07"):
		return floori(float(s) / BUG_07_ACORN_PER)     # ★バグ SK-07（1000）
	return floori(float(s) / ACORN_PER)                 # 正しい（500）
```

- `floori(820 / 500)` は 1.64 の小数点以下を切り捨てて 1。1000 で割ると 0.82 → 0
- 2つとも同じ場所なので、同じ日には1つしか出ない（`group: "reward"`）

### SK-08 左の壁ぎりぎりまで寄せられない

- **原因メモ**: 左に寄せられる範囲の制限が、壁より70ピクセル内側になっていました
- **場所**: `_clamp_x()`

```gdscript
var lo := BIN_LEFT + r          # 左の限界（壁＋果物の半径）
if has_bug("SK-08"):
	lo += BUG_08_LEFT_GAP       # ★バグ SK-08: さらに70ピクセル内側
return clampf(x, lo, hi)        # x を lo〜hi の範囲に収める
```

- `clampf` は「はみ出した値を範囲の中に押し戻す」関数。範囲の数字を1つ間違えるだけで、端まで行けなくなる。**左右で動きが違う**ので、両端を試すと気づける

### SK-09 底の真ん中だけトランポリン

- **原因メモ**: 底の真ん中の部分だけ「跳ね返りの強さ」の設定が 0.95 になっていました
- **場所**: `start()`

```gdscript
# ★バグ SK-09
floor_mid.physics_material_override.bounce = 0.95 if has_bug("SK-09") else 0.0
```

- 底は「左・真ん中・右」の3つの部品でできていて、真ん中（横120ピクセル）だけ別の設定。`bounce`（跳ね返り）が 1 に近いほどよく跳ねる
- **物理エンジン**の設定ミス。見た目では区別できないので、落とす場所を変えて試すと気づける

### SK-10 ぶどうに当たるとくっつく

- **原因メモ**: ぶどうに別の果物が当たったとき、当たった果物をその場に固定する処理が間違って入っていました
- **場所**: `_on_contact()` と `_stick()`

```gdscript
if ranks.has(2):                              # ぶどう(2)とぶつかった
	if has_bug("SK-10"):
		# ★バグ SK-10
		var stuck := b if a.rank == 2 else a  # ぶどうじゃない方
		_stick.call_deferred(stuck)

func _stick(f):
	f.freeze_mode = RigidBody2D.FREEZE_MODE_STATIC
	f.freeze = true                           # 物理の動きを止めて、その場に固定
```

- `freeze`（凍らせる）＝物理の計算から外して動かなくする。ぶどう自身は止まらないので、ぶどうが動くと**当たった果物だけ空中に取り残される**（ららすけのスクショ1枚目）

### SK-13 デコポンを合体させるとりんご

- **原因メモ**: デコポン同士の合体だけ、1つ上ではなく2つ上の果物（りんご）を作っていました
- **場所**: `_resolve_merge()`

```gdscript
if a.rank == 3 and b.rank == 3:      # デコポン同士
	if has_bug("SK-13"):
		new_rank = 5                 # ★バグ SK-13: 正しくは 4（かき）
```

## 5. おまけ：仕込んでいない本物のバグ（ららすけが見つけたもの）

2日目のテストプレイで、ららすけが「同じ色の球に当たるとずっと跳ねてる」と報告してくれた。これは**くろすけが作るときにうっかり入れてしまった本物のバグ**だった。

- **起きたこと**: SK-10 でくっついて止まった果物に、同じ果物が当たっても合体しない
- **原因**: 合体の処理を「2つのうち、ID（番号）が小さい方の果物だけ」がやるようにしていた（2回合体しないように）。ところが、止まった（freeze した）果物は「ぶつかった」という通知を出さない。止まった方の ID が小さいと、**誰も合体の処理をしなかった**

```gdscript
# 直す前（バグ）
if a.get_instance_id() > b.get_instance_id():
	return          # ID が大きい方は何もしない → 止まった相手が担当だと、誰も合体しない

# 直したあと
if a.merged or b.merged:
	return          # 「もう合体済み」の印だけで二重合体を防ぐ。どちらの側からでも合体できる
```

- 仕込んだバグ（SK-10）が、仕込んでいないバグを呼び出した＝**影響範囲**そのもの
- 直したあと、「同じことがまた起きないか」を確かめる**回帰テスト**を `tools/test_suika.gd` に追加した

## 6. 用語のミニ辞典

| 言葉 | 意味 |
|---|---|
| 変数 | 値を入れておく箱。`var score := 0` |
| 関数（func） | ひとまとまりの処理に名前を付けたもの。`func acorns_for(s)` |
| if / else | 「もし〜なら」「そうでなければ」 |
| `A if 条件 else B` | 条件が正しければ A、違えば B を使う（1行で書く if） |
| true / false | 正しい／正しくない（はい／いいえ） |
| シグナル（signal） | 「こんなことが起きたよ」と別の部品に知らせる合図 |
| 当たり判定 | 物がぶつかるかどうかを決める、見えない形 |
| 物理エンジン | 重力や跳ね返りを計算して、物を自然に動かす仕組み |
| freeze | 物理の計算から外して、その場に止めること |
| マスタ（設定） | 報酬の数・文言・画像など、プログラムとは別に持っている設定データ |
| 回帰テスト | 一度直したバグが、また起きていないかを確かめるテスト |
| 影響範囲 | ある修正やバグが、別の場所に与える影響 |
