# 資料（docs）

ららくろそふとQA の開発資料。

| 資料 | 内容 |
|---|---|
| [design.md](design.md) | 企画書（コンセプト・章立て・1日の流れ・バグのデータ形式・1日目の内容・決定事項） |
| [dev-log.md](dev-log.md) | 開発の記録（どういう流れで作ったか・ららすけの要望と決定・次のゲームで使えるコツ） |
| [spec-day1.md](spec-day1.md) | 仕様書：1日目（実際にどう動くか。画面・ターン・バグ7つ・報告書・判定・修正確認・採点・メッセージ。テストのときはこれと比べる） |
| [spec-day2.md](spec-day2.md) | 仕様書：2日目（スイカゲーム。1日目からの変更点・日の切り替え・バグ14個） |
| [spec-day3.md](spec-day3.md) | 仕様書：3日目（神経衰弱 v1.4。リリースノート・デグレ・修正の副作用・バグ11個） |
| [bug-internals.md](bug-internals.md) | バグの裏側（32個のバグがコードの中でどう起きているか。スイッチの仕組み、原因、コードの抜き出し、用語のミニ辞典） |

資料を更新したら、企画書の「改訂履歴」と「決定事項」にも書き足すこと。
作業の区切り（作った・決めた・テストプレイの感想をもらった）ごとに dev-log.md にも追記すること。
仕様（動き・数字・文言）を変えたら spec-day1.md も直すこと。
